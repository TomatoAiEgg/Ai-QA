# 云服务器部署指南

本文档面向当前项目的初级可用版，目标是将项目部署到一台全新的 Linux 云服务器上。

推荐部署方式：

- 单机 Docker + Docker Compose
- Nginx 反向代理
- PostgreSQL
- Redis
- Spring Boot 后端
- Vue 前端静态资源

如果只是先上线自用或小范围测试，优先使用 Docker 方案。文末附带一个可选的 K8s 试玩思路。

## 1. 服务器建议配置

当前项目初级版推荐最低配置：

- CPU：4 核
- 内存：4 GB
- 硬盘：30 GB 以上
- 系统：Ubuntu 22.04 LTS 或 Debian 12

说明：

- 4C4G 足够部署和小规模使用
- 硬盘主要会被 PostgreSQL、上传文档、向量数据和日志占用
- 如果后续文档量上来，建议增加磁盘或使用对象存储

## 2. 对外暴露端口

建议只暴露以下端口：

- `22`：SSH
- `80`：HTTP
- `443`：HTTPS

不建议直接暴露：

- `5432`：PostgreSQL
- `6379`：Redis
- `7000`：后端服务端口

这三个端口建议只在服务器本机或 Docker 内部网络使用。

## 3. 部署架构

推荐结构如下：

```text
浏览器
  ↓
Nginx
  ├─ /           → 前端静态页面
  ├─ /api/       → Spring Boot
  ├─ /ai/        → Spring Boot
  └─ /openapi/   → Spring Boot

Spring Boot
  ├─ PostgreSQL
  └─ Redis
```

说明：

- 前端最终以静态文件形式交给 Nginx 托管
- Nginx 负责反向代理后端接口
- `/ai/` 是流式聊天接口，必须关闭代理缓冲

## 4. 环境准备

### 4.0 推荐目录规划

如果是你自己维护的一台服务器，建议不要把软件、项目、日志都堆在一个目录里。

推荐结构：

```text
/opt/software   # 安装包、中间件、脚本
/opt/projects   # 项目代码或部署目录
/opt/logs       # 各项目运行日志
/opt/data       # PostgreSQL/Redis/上传文件等持久化数据
```

以当前项目为例，建议：

```text
/opt/projects/ai-qa
/opt/logs/ai-qa
/opt/data/ai-qa/postgres
/opt/data/ai-qa/redis
/opt/data/ai-qa/kb-files
```

说明：

- `software` 放 Docker、安装包、辅助脚本等
- `projects` 放项目部署文件和 compose 文件
- `logs` 单独放日志，方便排查和清理
- `data` 单独放数据库和上传文件，避免容器重建丢数据

### 4.1 安装 Docker

Ubuntu / Debian 可参考以下命令：

```bash
sudo apt update
sudo apt install -y ca-certificates curl gnupg lsb-release
sudo mkdir -p /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \
  https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo $VERSION_CODENAME) stable" \
  | sudo tee /etc/apt/sources.list.d/docker.list > /dev/null
sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
```

验证：

```bash
docker --version
docker compose version
```

将当前用户加入 Docker 组：

```bash
sudo usermod -aG docker $USER
```

重新登录后生效。

### 4.2 创建部署目录

```bash
mkdir -p ~/apps
cd ~/apps
git clone https://github.com/TomatoAiEgg/Ai-QA.git
cd Ai-QA
```

1. `susan_ai_schema.sql`

- 旧的业务结构和基础数据来自前两份 SQL


## 7. Docker 部署思路

推荐容器划分：

- `postgres`
- `redis`
- `backend`
- `nginx`

建议数据卷：

- PostgreSQL 数据目录
- Redis 数据目录
- 上传文件目录 `data/kb-files`
- Nginx 配置目录

后端容器建议限制 JVM 内存，例如：

```bash
-Xms512m -Xmx1024m
```

因为 4GB 内存服务器不适合让 Java 默认无限膨胀。

## 8. Nginx 配置要点

Nginx 至少要处理三类代理：

- `/api/`
- `/ai/`
- `/openapi/`

其中 `/ai/` 是流式接口，必须关闭缓冲。

示例：

```nginx
server {
    listen 80;
    server_name your-domain.com;

    root /opt/ai-qa/ui/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://127.0.0.1:7000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /ai/ {
        proxy_pass http://127.0.0.1:7000;
        proxy_http_version 1.1;
        proxy_buffering off;
        proxy_cache off;
        proxy_set_header Connection "";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    location /openapi/ {
        proxy_pass http://127.0.0.1:7000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```

## 9. 后端运行参数建议

当前项目里很多配置已经适合用环境变量接管，至少建议覆盖这些：

```properties
spring.datasource.url=${DB_URL}
spring.datasource.username=${DB_USERNAME}
spring.datasource.password=${DB_PASSWORD}

spring.data.redis.host=${REDIS_HOST}
spring.data.redis.port=${REDIS_PORT:6379}
spring.data.redis.password=${REDIS_PASSWORD:}

spring.ai.openai.api-key=${QWEN_API_KEY}
```

后端手工启动示例：

```bash
java -Xms512m -Xmx1024m \
  -jar ai-qa.jar \
  --server.port=7000 \
  --DB_URL=jdbc:postgresql://127.0.0.1:5432/Ai-QA \
  --DB_USERNAME=postgres \
  --DB_PASSWORD=123456 \
  --REDIS_HOST=127.0.0.1 \
  --REDIS_PORT=6379 \
  --REDIS_PASSWORD=123456 \
  --QWEN_API_KEY=你的Key
```

当前项目已经补了文件日志配置：

- `info` 日志：`${LOG_PATH}/yyyy-MM-dd-info.log`
- `error` 日志：`${LOG_PATH}/error.log`，并按天归档 `${LOG_PATH}/yyyy-MM-dd-error.log`

默认日志目录是项目根目录下的 `logs/`，生产环境建议通过环境变量改为：

```bash
LOG_PATH=/opt/logs/ai-qa
```

初级版上线后建议至少做好这几件事：

- 配置日志滚动

- 不要把数据库和 Redis 暴露公网

## 13. K8s 试玩方案

如果你只是想练手，不建议一上来就把这个项目正式跑在 K8s 上，但可以用来熟悉流程。

推荐试玩方式：

- 单节点 `k3s`
- 或本地 `minikube`

练手目标：

1. 将后端构建成镜像
2. 将前端静态资源用 Nginx 镜像托管
3. 将 PostgreSQL、Redis 跑成 Deployment 或 StatefulSet
4. 用 Service 暴露后端
5. 用 Ingress 暴露 Nginx

最小练手对象：

- `backend Deployment`
- `frontend-nginx Deployment`
- `postgres StatefulSet`
- `redis Deployment`
- `Ingress`

不建议现在就做的事：

- Helm 改造
- HPA 自动扩缩容
- 多环境流水线
- Service Mesh

因为你现在目标是先把项目稳定上线，不是做一套完整云原生平台。

## 14. 推荐推进顺序

建议按这个顺序执行：

1. 本地把 Docker 化部署文件补齐
2. 服务器安装 Docker
3. 导入数据库 SQL
4. 跑通 PostgreSQL、Redis、后端、Nginx
5. 用域名访问并验证 SSE 聊天
6. 最后再考虑 HTTPS 和 K8s 试玩

## 15. 当前阶段的建议结论

你现在最合适的目标是：

- 先在云服务器上用 Docker 跑起来
- 验证基础功能稳定可用
- 后续再逐步补权限、审计、K8s、CI/CD 等扩展能力

- `docker-compose.yml`
