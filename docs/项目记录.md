## v1.0.0 (2026-03-13) - 从 Ollama 迁移至千问模型

### 变更概述
将项目从 Ollama 本地部署模型迁移至阿里千问（DashScope 兼容 OpenAI 接口）。

### 变更原因
- 无需本地部署，降低资源消耗
- 云端 API 响应更快，模型能力更强

### 核心变更

| 文件 | 变更内容 |
|------|----------|
| `pom.xml` | 删除 Ollama 依赖，保留 OpenAI  starter（千问兼容） |
| `ChatMemoryConfiguration.java` | 改用 `OpenAiChatModel` 和 `OpenAiEmbeddingModel` |
| `AiService.java` | 删除 OllamaIntegration，直接使用 QwenIntegration |
| `AiController.java` | 端点 `/ai/chatByOllama` → `/ai/chat` |
| `chat.html` | 删除 Ollama 模型选项 |
| `application.properties` | 删除 Ollama 配置，保留千问配置 |
| **删除** | `OllamaIntegration.java` |

### 环境配置

**application.properties**:
```properties
spring.ai.openai.api-key=${QWEN_API_KEY}
spring.ai.openai.base-url=https://dashscope.aliyuncs.com/compatible-mode
spring.ai.openai.chat.options.model=qwen3-max
spring.ai.openai.embedding.options.model=text-embedding-v2
```

**设置环境变量**:
```cmd
# Windows
set QWEN_API_KEY=你的千问 API 密钥

# Linux/Mac
export QWEN_API_KEY=你的千问 API 密钥
```

## v1.0.1 (2026-03-13) - 修复流式响应显示问题

### 问题描述
前端发送消息后，控制台有响应数据但页面不显示 AI 回复。

### 根本原因
1. 前端 CDN 资源加载失败（jsdelivr 超时）
2. 后端 `Flux<String>` 未正确转换为 SSE 格式

### 修复内容

| 文件 | 变更 |
|------|------|
| `chat.html` | CDN 地址改为 cloudflare，添加调试日志 |
| `AiController.java` | 返回类型改为 `Flux<ServerSentEvent<String>>` |

### 关键代码
```java
@PostMapping(value = "/ai/chat", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
public Flux<ServerSentEvent<String>> chat(@RequestBody String question,
                         @RequestParam("conversationId") UUID conversationId) {
    return aiService.chatByStream(question, conversationId, "qwen")
            .map(text -> ServerSentEvent.builder(text).build());
}
```

## v1.0.2 (2026-03-15) - 文档切片器配置与优化

### 变更概述
新增可配置的文档切片器、优化知识库服务统计功能、新增文档切片预览接口。

### 1. 新增 DocumentSplitterConfiguration

**文件**: `src/main/java/cn/net/susan/ai/config/DocumentSplitterConfiguration.java`

**配置参数**（可通过 `application.properties` 调整）:

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `defaultChunkSize` | 512 | 每个文档块的目标大小（token 数） |
| `minChunkSizeChars` | 128 | 每个文档块的最小字符数 |
| `minChunkLengthToEmbed` | 5 | 被嵌入的块的最小长度 |
| `maxNumChunks` | 10000 | 单个文档生成的最大片段数 |
| `keepSeparator` | true | 是否保留分隔符（如换行符） |

**配置示例**:
```properties
susan.document.splitter.default-chunk-size=512
susan.document.splitter.min-chunk-size-chars=128
susan.document.splitter.min-chunk-length-to-embed=5
susan.document.splitter.max-num-chunks=10000
susan.document.splitter.keep-separator=true
```

### 2. 优化 KnowledgeBaseService

**变更内容**:
- 注入 `TokenTextSplitter` 替代硬编码
- 增强文档上传统计（平均大小、最小/最大、重叠率）
- 添加元数据（文件名、上传时间、切片索引）

**返回示例**:
```
文档上传并处理成功，共生成 15 个片段 (平均每个片段 485 字符，重叠率 23.5%)
```

### 3. 新增预览接口

**接口**: `POST /ai/preview-chunks`

**说明**: 上传文件后先不存储，仅返回切片结果用于预览

**返回示例**:
```json
[
  {"index": 0, "content": "第一段内容...", "length": 512},
  {"index": 1, "content": "第二段内容...", "length": 489}
]
```

### 4. AiController 变更
- 注入 `TokenTextSplitter` 依赖
- 新增 `previewChunks()` 方法

## 技术说明

### SSE 流式响应格式
```
data: 你
data: 好
data: ，
```

### 重叠率计算
```
重叠率 = (总切片字符数 / 原始字符数 - 1) × 100%
```
- 重叠率越高：上下文保留越好，向量存储成本越高

### TokenTextSplitter 工作原理
1. **文本分块**: 按 token 数切分长文档
2. **重叠处理**: 相邻块保留重叠内容
3. **分隔符保留**: 可选择保留换行符等格式
