# AI-QA 项目记录

**当前版本**: `v2.7.0`  
**最后更新**: `2026-04-11`  
**仓库地址**: `https://github.com/TomatoAiEgg/Ai-QA`

## 最近更新

### v2.7.0

- 账号体系收口为邮箱登录和邮箱注册，前端不再展示手机号登录入口。
- 注册时根据邮箱判断是否已存在，已注册邮箱会提示用户直接登录。
- 登录和注册都增加服务端验证码校验，验证码存入 Redis 并一次性消费，防止绕过前端刷接口。
- 登录接口只接受邮箱、密码和验证码参数，手机号登录兼容入口已从前端关闭。
- 对话工作台顶部昵称改为可点击按钮，支持弹框输入新昵称并实时更新当前登录态。
- 新增后端昵称更新接口，更新成功后返回最新 session，前端同步刷新本地用户信息。
- 优化知识库创建/编辑弹框，改为云控制台风格配置面板，增加顶部说明、输入提示、标签说明和移动端按钮适配。
- 云服务器维护方式明确为拉取或上传最新代码后执行 `docker compose up -d --build`，由 Compose 统一更新前后端和中间件容器。

### v2.6.0

- 完成后端模块重构，按 `auth`、`chat`、`conversation`、`document`、`knowledgebase`、`openapi` 拆分控制层和服务层。
- 文档异步处理链路正式接入 RocketMQ，文档上传、消费、重试、状态流转解耦。
- 文档处理增加幂等保护，避免 MQ 重投或重复消费导致向量数据脏写。
- 文档预览改为直接预览原始文件，不再把切片内容返回前端。
- 新增文档存储抽象，支持本地存储和 MinIO，两种实现可切换。
- 默认文档存储切换为 MinIO，新上传文件进入对象存储。
- 文档预览对 MinIO 文件改为签名地址跳转，本地文件仍支持服务端流式预览。
- 文档上传链路优化：
  - 上传时顺手计算文件哈希，减少重复 IO。
  - 向量化改为批量调用。
  - 向量写库改为批量插入。
- 前端知识库页支持：
  - 文档状态轮询刷新
  - 失败文档重试
  - 原文件预览
- 前后端文案统一回中文，避免接口成功但前端提示被覆盖。
- 修复聊天页 `v-html` 渲染带来的 XSS 风险。
- OpenAPI token 改为摘要存储，不再明文落库。
- Redis 序列化收紧，去掉过宽的默认反序列化配置。
- 全局异常改为统一返回安全文案，避免内部错误直接泄漏到前端。
- 登录/注册/退出流程补了登录态缓存一致性兜底，减少“接口失败但登录态已变化”的问题。

### 文档处理链路

1. 用户上传文档
2. 文件写入对象存储
3. 文档记录入库
4. 发送 RocketMQ 文档处理消息
5. 消费者处理文档：
   - 读取原始文件
   - 切片
   - 批量向量化
   - 批量写入向量库
   - 更新文档状态

## 当前默认组件

- MinIO 文档存储

## 当前推荐维护方式

服务器可以直接在项目目录执行：

```bash
docker compose up -d --build
```

如果服务器访问 GitHub 不稳定，可以本地压缩项目代码上传到服务器，解压后在项目根目录执行同一条命令。数据库、Redis、MinIO、RocketMQ 的数据目录只要没有删除，会继续复用原数据。

## 仍需关注

- 前端主包仍偏大，Vite 构建会提示 chunk 过大。
- 旧的本地文档数据还未迁移到 MinIO，只兼容读取。
- 自动化测试仍偏少，尤其是文档处理、MQ、认证、验证码和缓存一致性链路。
