## 最近更新

### v2.4.0
- 接入 Redis，新增 `spring-boot-starter-data-redis`、`spring-boot-starter-cache` 和 `sa-token-redis-jackson`
- Sa-Token token 与会话信息改走 Redis，登录后会按 token 缓存用户登录态
- 前端新增本地登录态持久化，浏览器会保存当前用户信息和 token，并在请求时自动携带
- 会话列表、会话消息、知识库列表、知识库详情、文档列表、文档预览增加 Redis 读缓存
- PostgreSQL 继续承担写入和更新，读请求优先通过 Redis 缓存返回
- `knowledge_base_documents` 新增 `user_id`，文档从“通过知识库间接归属用户”升级为“直接归属用户”
- 上传文档时写入 `user_id` 和向量 `user_id` 元数据，文件也按用户目录落盘
- 查询、删除、预览文档统一按 `user_id` 做隔离
- 修复工作台初始化时 `/api/auth/session` 未登录错误被错误包装的问题，恢复为标准 `401`
- `docker-compose.yml` 补充 Redis 服务，方便本地一键启动

### v2.3.0
- 数据访问层从原始 JDBC 仓库切换到 MyBatis-Plus，新增实体、Mapper 和统一建表脚本 `schema.sql`
- 补齐 PostgreSQL `UUID` 映射，修复历史对话和知识库列表接口返回 `id = null`
- 解决“进入页面不加载历史对话、点击历史对话无反应”
- 对齐前后端接口参数，聊天请求统一支持 `model`、`useRag`、`kbId`
- 修复会话标题更新接口，兼容前端 JSON body 调用
- 补齐文档删除接口和文档预览接口，上传文档后可重新切片预览
- RAG 检索按 `kbId` 过滤，删除文档或知识库时同步清理向量数据
- 知识库及文档表改为自动建表，新环境不再依赖手工初始化
- 修复 SSE 多行 `data:` 解析，流式输出时保留 Markdown 换行
- 修复流式 Markdown 渲染，AI 回复过程中即可展示样式，无需刷新
- 重做前端工作台布局，新增主题切换
- 重做知识库管理界面，支持直接点击知识库卡片进入详情
- 支持编辑知识库名称和描述
- 优化文档列表展示
- 修复知识库文档数量首次进入不显示的问题

### v2.2.0
- 统一聊天接口参数，前端会真实传递 `model`、`kbId`、`useRag`
- 修复会话标题修改接口，后端兼容 JSON body
- 补齐文档删除接口 `/ai/documents/{id}`
- RAG 检索支持按知识库 `kbId` 过滤
- 上传文档时补充 `doc_id`、`kb_id` 元数据，删除文档和知识库时同步清理向量库
- 知识库相关表支持自动建表，新环境可直接启动
- 聊天页新增知识库选择，RAG 对话可指定知识库
- 修复推荐问题失败后页面卡在“正在回复”的状态
- 修复 SSE 流式解析和 Markdown 渐进渲染

## 运行要求

后端：
- Java 17
- PostgreSQL
- Redis
- `QWEN_API_KEY` 环境变量

前端：
- Node.js
- `npm install`
- `npm run dev`

后端启动示例：

```powershell
$env:JAVA_HOME='D:\Javasource\jdk-17.0.9'
$env:PATH="$env:JAVA_HOME\bin;D:\Javasource\apache-maven-3.9.2\bin;$env:PATH"
mvn spring-boot:run
```

## 说明

- 会话、知识库和文档数据目前统一走 MyBatis-Plus
- 表结构初始化由 `schema.sql` 负责
- 登录态和读缓存走 Redis，PostgreSQL 作为主数据源负责写入和更新
- 文档预览依赖上传后保存的原文件；旧数据如果没有 `storage_path`，可能无法直接预览
