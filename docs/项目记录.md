### 业务逻辑变更

#### 1. RAG 流程新增 Rerank 步骤

**修改文件**: `AiService.java`

**流程变更**:
```
【v1.0.2 流程】
用户提问 → 向量检索 → 构建 Prompt → 千问 API → 返回答案

【v1.1.0 流程】  
用户提问 → 向量检索 → Rerank 重排序 → 构建 Prompt → 千问 API → 返回答案
                                        ↑
                                   新增步骤
```

**代码变更**:
```java
// 注入 RerankService
private final RerankService rerankService;

// 在向量检索后增加重排序
List<Document> documents = vectorStore.similaritySearch(...);

if (rerankService.isEnabled()) {
    documents = rerankService.rerank(question, documents);
    // 过滤低分文档，按相关性降序排列
}
```

#### 2. RerankService 实现

**新建文件**: `src/main/java/cn/net/susan/ai/service/RerankService.java`

**核心逻辑**:
```java
public List<Document> rerank(String query, List<Document> documents) {
    // 1. 提取文档内容
    List<String> contents = documents.stream()
            .map(Document::getContent)
            .toList();

    // 2. 调用阿里百炼 Rerank HTTP API
    Request request = new Request.Builder()
            .url("https://dashscope.aliyuncs.com/api/v1/services/rerank/...")
            .post(RequestBody.create(jsonBody, JSON))
            .addHeader("Authorization", "Bearer " + apiKey)
            .build();

    // 3. 解析响应，获取相关性评分
    // 4. 过滤低于阈值的文档 (min-score=0.5)
    // 5. 按评分降序排序，返回 Top-N (top-n=3)
}
```

**配置项**:
```properties
ai.service.rerank.enabled=true
ai.service.rerank.model=qwen3-rerank
ai.service.rerank.min-score=0.5    # 最低分数阈值
ai.service.rerank.top-n=3          # 返回文档数
```

#### 3. 向量模型升级

**配置变更**:
```properties

# 向量维度 (v3 输出 1024 维)

```

**影响**:
- 需重建向量索引（旧数据在 `vector_store_768` 表）
- 首次启动自动创建 `vector_store_1024` 表

#### 3. 新增预览接口

**接口**: `POST /ai/preview-chunks`

**业务逻辑**:
```java
@PostMapping("/ai/preview-chunks")
public Object previewChunks(@RequestParam("file") MultipartFile file) {
    // 1. 保存文件到临时目录
    Path tempFile = Files.createTempFile("kb_preview_", ...);
    
    // 2. 使用 Tika 读取文档内容
    TikaDocumentReader reader = new TikaDocumentReader(...);
    List<Document> documents = reader.read();
    
    // 3. 文本切分
    List<Document> splitDocuments = tokenTextSplitter.apply(documents);
    
    // 4. 清理临时文件
    Files.deleteIfExists(tempFile);
    
    // 5. 返回切片预览（不存储）
    return splitDocuments.stream()
            .map(doc -> Map.of("index", ..., "content", ..., "length", ...))
            .toList();
}
```

## v1.0.1 (2026-03-13) - 修复流式响应

### 问题描述
前端发送消息后，控制台有响应数据但页面不显示 AI 回复。

### 根本原因
1. 前端 CDN 资源加载失败（jsdelivr 超时）
2. 后端 `Flux<String>` 未正确转换为 SSE 格式

### 修复内容

#### 1. 后端 SSE 格式修复

**文件**: `AiController.java`

```java
// 【修复前】返回原始文本流
@PostMapping(value = "/ai/chat", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
public Flux<String> chat(...) {
    return aiService.chatByStream(...);
}

// 【修复后】转换为 SSE 格式
public Flux<ServerSentEvent<String>> chat(...) {
    return aiService.chatByStream(...)
            .map(text -> ServerSentEvent.builder(text).build());
}
```

**SSE 格式示例**:
```
data: 你
data: 好
data: ，
```

#### 2. 前端 CDN 地址修复

**文件**: `chat.html`

```html
<!-- 修改前 -->
<script src="https://cdn.jsdelivr.net/npm/marked/marked.min.js"></script>

<!-- 修改后 -->
<script src="https://cdnjs.cloudflare.com/ajax/libs/marked/12.0.0/marked.min.js"></script>
```

### 文件变更清单

| 文件 | 变更 |
|------|------|
| `AiController.java` | 返回类型改为 `Flux<ServerSentEvent<String>>` |

## 技术架构

### RAG 完整流程 (v1.1.0)

```
┌─────────────────────────────────────────────────────────────┐
│  用户提问                                                    │
└─────────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────────┐
│  步骤 1: 保存用户问题到数据库 (conversation_messages)          │
└─────────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────────┐
│  步骤 2: 向量检索 (Vector Search)                            │
│  - 调用 text-embedding-v3 将问题转为 1024 维向量              │
│  - 在 pgvector 中查询相似文档 (Top-5, 相似度>0.6)            │
└─────────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────────┐
│  步骤 3: Rerank 重排序 (新增)                                │
│  - 调用 qwen3-rerank API 计算相关性分数                      │
│  - 过滤分数 < 0.5 的文档                                      │
│  - 按分数降序返回 Top-3                                      │
└─────────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────────┐
│  步骤 4: 构建 Prompt                                         │
│  - 系统提示 + 历史对话 + 上下文信息 + 用户问题               │
└─────────────────────────────────────────────────────────────┘
                          ↓
┌─────────────────────────────────────────────────────────────┐
│  步骤 5: 调用千问 API (流式响应)                              │
│  - qwenIntegration.chatByStream()                           │
│  - 逐字返回给前端 (打字机效果)                               │
│  - 累积完整回复保存到数据库                                  │
└─────────────────────────────────────────────────────────────┘
```

### 向量检索 SQL 示例

```sql
-- pgvector 相似度搜索 (HNSW 索引)
SELECT embedding, chunk_content, metadata
FROM vector_store_1024
ORDER BY embedding <-> ?::vector  -- 问题向量
LIMIT 5;
```

### 文档切片流程

```
原始文档 (PDF/Word/TXT)
       ↓
   Tika 解析
       ↓
   完整文本
       ↓
TokenTextSplitter 切片
       ↓
   文档片段列表
       ↓
   向量嵌入 (Embedding)
       ↓
   pgvector 存储
```

## 注意事项

1. **API 密钥**: 通过环境变量 `QWEN_API_KEY` 设置，不要提交到版本控制
2. **向量维度**: text-embedding-v3 使用 1024 维，旧数据需重新上传
3. **Rerank 延迟**: 每次 RAG 对话增加约 200-500ms
4. **免费额度**: Embedding 和 Rerank 各有 50-100 万/月免费调用
